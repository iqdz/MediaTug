--------------------------------------------------------
1. What Media Tug is
--------------------------------------------------------
Media Tug is a keyboard-first, screen reader friendly media player and
downloader for Windows. It was designed with NVDA/JAWS users as the
primary audience from the start, so it relies on:

  - Native wxWidgets controls (standard Windows dialogs and widgets)
  - Spoken announcements handed straight to the running screen reader
    (NVDA, JAWS and others) through accessible_output2, in the user's
    own voice and settings; when no screen reader is running they are
    shown on screen instead. Media Tug has no voice of its own.
  - Sound cues: system-ready.wav on startup and complete.wav when a
    search finishes
  - No custom graphics-heavy UI that could confuse a screen reader

At startup the app plays the system-ready cue and moves keyboard focus
natively to the search box, announced by the screen reader itself.
About two seconds later a screen reader, if one is running, says
"Harrith Welcomes You" (spelled that way so voices say the name right)
without interrupting. Nothing is shown or spoken for it otherwise.

2. Current feature state (1.0.0)
--------------------------------------------------------
Search / play:
  - Search YouTube and other supported sites through yt-dlp
  - Paste any supported link into the search box and press Enter
  - Playlist/channel links are detected automatically and open a
    download confirmation ("Start Download: Playlist or Channel");
    playlist/channel downloads are saved into a 'Playlists' subfolder
  - Results list shows one item per line with duration and other info;
    pressing Down Arrow on the last item loads more results (10 at a
    time)
  - Enter plays the selected result; the context menu offers download
    options
  - Ctrl+Shift+V plays the selected item with video (slower to start)

Player:
  - Dedicated modal player window that captures keyboard focus
  - Space or Ctrl+P: play/pause
  - Ctrl+M: mute/unmute
  - Up/Down Arrows: volume
  - Left/Right Arrows: seek
  - Escape or Ctrl+W: close the player
  - Ctrl+D inside the player downloads the currently playing track
  - Ctrl+L inside the player copies the currently playing link
  - Ctrl+Shift+V shows the video for the currently playing audio in a
    separate window for sharing with a sighted person

Downloads:
  - Save as audio or video. Settings > Advanced download options picks
    the video format (MP4, MKV, WebM, MOV, AVI) and its quality, and
    the audio format (MP3, M4A (AAC), Opus, OGG Vorbis, FLAC, WAV,
    ALAC) and its quality; every download after OK uses exactly those
  - Fast by default: aria2c with 16 connections when present, yt-dlp
    downloading up to 8 pieces at once in 10 MB parts, and formats
    chosen so MP4, WebM, M4A and Opus need no re-encoding
  - A progress bar under the search box shows each download; screen
    reader users also hear progress every five seconds
  - Download folder, audio quality, video quality, skip seconds,
    volume step, cache retention and more are set in Settings (Alt+S)
  - aria2c (when present) speeds up save-to-disk/channel/video-fetch
    downloads with up to 16 parallel connections
  - ffmpeg is used for audio extraction/conversion and thumbnail
    embedding
  - Browser cookies support (choose a browser source or a cookies.txt
    file) for sites that need them
  - Downloads run in the background and announce progress every few
    seconds
  - If a download attempt with cookies fails, it retries once without
    them automatically

Favorite Channels (Alt+F, or the button after Help):
  - A saved list of YouTube channels, each row reading the channel
    name and how many new videos it has had since it was last opened
    in Media Tug
  - Focus starts in the list; one Tab reaches "Add a channel URL"
    (focus starts there when the list is empty). Add opens an edit
    field, already filled in when the clipboard holds a channel link
  - Enter opens a channel: its videos fill the main results list,
    newest first, and work like search results (Enter plays, the
    context menu downloads, Down Arrow on the last item loads more).
    Opening a channel resets its new video count
  - F5 checks every channel for new videos; Delete removes a channel
    after a confirmation; Escape closes
  - Saved in data\favorite_channels.json

Playback cache:
  - Play-now items are cached under data\playback_cache and pruned by
    age according to the retention setting (1/2/7/30 days)
  - Shift+Alt+C clears the playback cache manually

Settings & preferences (Alt+S):
  - Download path (with a sensible default: Downloads, then Documents,
    then profile root)
  - Download format: MP3 Audio or video
  - Video quality / audio quality / skip seconds / volume step
  - Debug logging toggle (writes media_tug_debug.log)
  - Use browser cookies: source selection or a cookies file path
  - Cache retention
  - Auto-paste clipboard option (pastes links when the window regains
    focus)

Accessibility extras:
  - Visual hint panel (plain painted text) used for sighted people
    sharing the screen; intentionally not exposed to the MSAA/UIA
    accessibility tree so NVDA/JAWS cannot read it
  - Activity Log (scrollback) plus a status bar for spoken
    announcements
  - Screen reader detection via SPI_GETSCREENREADER; some alerts only
    speak when a screen reader is active

Help and About:
  - Alt+H opens Help (hotkey reference)
  - The About page (button near the top) states the app name, author
    (Harith Alhamdani), version read from VERSION.txt, hotkeys,
    licensing of bundled components, and links to supported sites,
    the GitHub repository, contact email, and support page

3. Hotkeys reference (as shown in the app)
--------------------------------------------------------
  Control+F         Focus the search box
  Control+D         Download selected item(s) from results, or the
                    currently playing track inside the player
  Control+L         Copy the selected link (or the playing link)
  Control+Shift+E   Share the selected link by email
  Control+Shift+O   Open the selected link in your web browser
  Control+Shift+V   Play the selected item with video
  Alt+S             Open Settings & Preferences
  Alt+H             Open Help
  Alt+F             Open Favorite Channels
  Shift+Alt+C       Clear the playback cache
  Enter             Play the selected result
  Escape            Clear and close the results list (from the list, or
                    from the search box while results show); close the
                    player or a dialog
  Space / Ctrl+P    Play or pause (player)
  Ctrl+M            Mute (player)
  Up / Down Arrows  Volume (player)
  Left / Right      Seek (player)
  Ctrl+W            Close player window
  Context menu key  Download options on a result

5. Running from source (development)
--------------------------------------------------------
  1. Install Python 3 (the project uses pip --target local folders).
  2. Double-click run.bat, or run it from a Command Prompt.

run.bat will:
  - Create libs\ and pip-install wxPython, curl_cffi, and python-vlc
    into it when missing
  - Fetch/version-check yt-dlp nightly, ffmpeg, aria2c, and the VLC
    engine into dependencies\ (used directly in dev mode)
  - Check for Deno and install it via winget if missing (yt-dlp needs
    it to solve YouTube's playback challenge)
  - Launch media_tug.py

Setup output is captured to logs\run.log.

--------------------------------------------------------
6. Building the portable app
--------------------------------------------------------
Run: build.bat

What it does:
  1. Cleans previous build/dist/release folders
  2. Ensures yt-dlp nightly is up to date in dependencies\yt-dlp
  3. Runs PyInstaller from media_tug.spec (onedir output named app)
  4. Assembles release\MediaTug\ with app\, cookies\, data\, logs\,
     tools\; copies VERSION.txt into the release root and beside the
     exe so the About page can read the version at runtime
  5. Fetches the VLC engine into release\MediaTug\app
  6. Fetches ffmpeg (ffmpeg.exe, ffprobe.exe) into release\MediaTug\tools
  7. Fetches aria2c.exe into release\MediaTug\tools (optional but
     recommended; downloads still work without it, just slower)

The console prints the version banner at the start:
      === Media Tug build: version 1.0.0 ===

Output: release\MediaTug\ IS the portable app - copy it anywhere and
run app\media_tug.exe. Build output is saved to build.log.

--------------------------------------------------------
7. Building the MSI installer (optional)
--------------------------------------------------------
Prerequisite: WiX Toolset v3 (wix314.exe). Run build_installer.bat
AFTER build.bat so release\MediaTug\app and release\MediaTug\tools
exist.

What it does:
  - harvests every file under release\MediaTug\app (AppFiles.wxs)
    and release\MediaTug\tools (ToolsFiles.wxs) with heat.exe
  - compiles installer\installer.wxs + the two fragments with candle.exe
  - links release\installer\MediaTugSetup.msi with light.exe
  - saves full output to release\installer\output.log

Installer behavior:
  - Per-user install; no admin rights needed
  - Installs to %USERPROFILE%\MediaTug (sibling of Documents,
    Downloads, Music)
  - Minimal wizard: Welcome -> Ready -> Finish (License page skipped)
  - Native Windows dialogs throughout (screen reader friendly)
  - Adds Start Menu entry and Desktop shortcut
  - Finish dialog has "Launch Media Tug now" checkbox
  - Uninstall removes app\ and the shortcuts but deliberately keeps
    cookies\, data\, and logs\ (user settings and cache survive)

8. Versioning workflow
--------------------------------------------------------
- VERSION.txt at the repo root is the single source of truth for the
  app version shown on the About page (currently: 1.0.0).
- To bump the version: edit VERSION.txt only. No code change needed.
- build.bat reads VERSION.txt, prints it in the console, and copies it
  into the release folder (root and app\), so the built app's About
  page states the same version the build was made with.
- media_tug.py reads VERSION.txt at startup from next to the exe, from
  _internal\ (PyInstaller 6.x data layout), or from the portable root;
  if the file is missing it falls back to "unknown" and never crashes.
- The MSI Version in installer\installer.wxs must stay in sync manually (WiX
  requires four parts, e.g. 1.0.0.0 for version 1.0.0).

--------------------------------------------------------
9. Data, privacy, and maintenance
--------------------------------------------------------
- data\media_tug_settings.json stores user settings.
- data\playback_cache\ holds recently played/cached media files and is
  pruned by the retention setting.
- cookies\ and browser-cookie usage follow the user's Settings choice;
  the app can also use a cookies.txt file.
- logs\ contains media_tug_debug.log (when debug logging is enabled)
  and vlc_native.log (native VLC diagnostics).
- The app verifies its data/log folders are writable at startup and
  warns clearly if they are not (e.g. an MSI installed under another
  user's account).
